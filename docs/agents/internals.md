## Code layout

The module is `github.com/ivanklee86/releash`, laid out per [Organizing a Go module](https://go.dev/doc/modules/layout) and argonap's CLI pattern.

| Path | What it holds |
|---|---|
| `main.go` | Cobra and viper wiring only: `NewRootCommand`, `execute`, `run`, version resolution and flag binding. Having `main` at the module root is what makes `go install github.com/ivanklee86/releash@<version>` work. |
| `internal/releash/` | The orchestrator: `Config`, the `Releash` type built with `New` or `NewWithConfig`, and the exit code constants from [ADR 0004](../adrs/0004-exit-code-contract.md). |
| `Taskfile.yaml`, `tasks/go.yaml` | Developer and CI tasks (see [Tasks](#tasks)). |
| `.golangci.yml` | golangci-lint config: the `standard` linter set plus the `gofmt` and `goimports` formatters. |
| `.github/workflows/ci.yaml` | CI for pull requests and `main` (see [CI](#ci)). |
| `.github/actions/setup-task/` | Composite action that installs a pinned Task, cached between runs. |
| `.devcontainer/` | The devcontainer, generated by gantry from the `ivanklee86/devcontainers` Go base and `releash.libsonnet`. Regenerate with `gantry build --config gantry.yaml --write` in that folder. |
| `.pre-commit-config.yaml`, `.markdownlint-cli2.yaml`, `renovate.json` | prek hooks, markdownlint config and Renovate config (see [Quality tooling](#quality-tooling)). |

### The orchestrator pattern

`main.go` maps options into a `releash.Config`, builds a `Releash`, and calls its methods. Everything the CLI does lives on `Releash`, which writes to its swappable `Out` and `Err` writers and returns an exit code instead of calling `os.Exit`. `main` is the only place that calls `os.Exit`, so tests drive the CLI by calling `execute(args, stdout, stderr, version)` and asserting on the buffers and the returned code.

`run` is the one place that maps outcomes to exit codes. It turns every error cobra returns into exit 2, because in M1 all of them come from parsing the command line, and it recovers a panic in a command, reports it on stderr and exits 1, as ADR 0004 requires, instead of Go's default exit 2. Cobra's own error and usage printing is silenced, because cobra would print usage to stdout and stdout must stay empty on errors.

### Versions

`releash --version` prints `main.version` if it was injected with `-ldflags "-X main.version=<version>"` (release builds, M5). Otherwise it prints the main module version from `runtime/debug.ReadBuildInfo`, which is the module version for `go install` and a VCS pseudo-version for `go build` in a git checkout. If neither is available, or build info reports `(devel)`, it prints `dev`.

### Options and environment variables

releash uses the environment variable names from spec 0001 (`UNLEASH_URL`, `UNLEASH_API_TOKEN`) rather than a common prefix, so each flag names its own. A flag opts in by carrying the `releash_env` annotation with the variable names, and `bindFlags` fills any such flag that was not given on the command line. Options take precedence over environment variables, an empty variable counts as unset, and there is no config file.

## Quality tooling

### prek hooks

`.pre-commit-config.yaml` is run by [prek](https://github.com/j178/prek), which the devcontainer installs as a git hook on creation. Run `prek run --all-files` to check the whole repository. The hooks are:

- whitespace, end-of-file, YAML, merge-conflict and large-file checks from `pre-commit/pre-commit-hooks`
- `golangci-lint fmt`, `golangci-lint run` and `go mod tidy -diff`, run from the devcontainer's golangci-lint, so the hook and `task go:lint` use the same version
- `markdownlint-cli2` over every Markdown file, configured by `.markdownlint-cli2.yaml`
- `renovate-config-validator`, run with `--strict --no-global` so `renovate.json` is checked as repository config and any warning or needed migration fails the hook

Hook versions are pinned by tag in `.pre-commit-config.yaml` and updated by Renovate.

### markdownlint

`.markdownlint-cli2.yaml` enables the default rules except where they fight the repository's doc style:

- `MD013` (line length) is off, because docs use full-length lines and code fences hold long CLI output.
- `MD024` (duplicate headings) applies to siblings only, because specs, ADRs and milestones repeat headings under different parents.
- `MD041` (first line is a heading) is off, because specs follow the Rust RFC template, which starts with a metadata list.
- `MD060` (table column style) is off, because tables use compact `|---|---|` delimiter rows.

Placeholders such as `<topic>` in prose are escaped (`\<topic\>`) or put in backticks, because GitHub drops them as unknown HTML tags otherwise.

### Renovate

`renovate.json` extends `config:recommended`, runs on Fridays, and waits five days (`minimumReleaseAge`) after a release before proposing it. It covers Go modules and the `go` directive in `go.mod` (bumped through `rangeStrategy: bump`), GitHub Actions, prek hooks, the devcontainer base image in `.devcontainer/Dockerfile`, and Docker images in `docker-compose.yaml`. Compose images and the devcontainer base image are pinned by tag and digest. The `devcontainer` manager is disabled: devcontainer features are maintained in the shared gantry base (`ivanklee86/devcontainers`), not in this repository. That also means Renovate never updates `.devcontainer/devcontainer-lock.json`. Refresh it with the Dev Containers CLI (`devcontainer upgrade --workspace-folder .`) after the gantry base changes a feature. Regex managers pick up versions the built-in managers cannot see:

- `go install <pkg>@<version>` lines in `tasks/go.yaml`
- Task's version in `.github/actions/setup-task/action.yml`
- `<TOOL>_VERSION` env values and octocov's `version` input in workflows, marked with a trailing `# <datasource>/<depName>` comment, e.g. `GORELEASER_VERSION: v2.0.0 # github-releases/goreleaser/goreleaser`

Updates are grouped into one pull request per group:

| Group | What it holds |
|---|---|
| `go` | Go modules (including tools pinned with `go install`), the Go version, and the devcontainer base image |
| `ci` | GitHub Actions, prek hooks, and CI tools pinned through `github-releases` comments (Task, prek, octocov, goreleaser) |
| `unleash` | The `unleashorg/unleash-server` image and the `github.com/Unleash/unleash-go-sdk` module |

Minor, patch, pin and digest updates automerge once CI passes, except for the cases below. Major updates never automerge. These always need a human:

- major updates of Go modules and the devcontainer base image
- any update of the Go version (the `go` directive in `go.mod`), because it must land together with the devcontainer base image tag: the devcontainer's golangci-lint is built with the image's Go, and golangci-lint fails on a `go` directive newer than the Go it was built with
- major updates of compose images (Postgres and the seed's Python image), because a new major can drop support that the pinned Unleash or the seed script relies on
- any update in the `unleash` group, because the integration tests are the only guard against behaviour changes there. Upgrade the seed script with the server image, since it uses the Admin API.

## Tasks

Run `task` with no arguments to format, lint, build and test. The tasks in `tasks/go.yaml` are included under the `go:` prefix.

| Task | What it does |
|---|---|
| `go:install` | Downloads module dependencies. |
| `go:install-ci` | Also installs golangci-lint, pinned to the version in the devcontainer base image. |
| `go:fmt` | Formats code with `golangci-lint fmt` (gofmt and goimports). |
| `go:lint` | Runs `golangci-lint run`. |
| `go:build` | Builds `bin/releash` without an injected version. |
| `go:test` | Runs `go test -v ./...`. |

## CI

`.github/workflows/ci.yaml` runs on pull requests and pushes to `main`. It has read-only `contents` permission by default and cancels superseded pull request runs. The `lint` job checks `gofmt`, then runs `task go:lint` and `task go:build`. The `test` job runs `task go:install` and `task go:test`. Both jobs run on `ubuntu-26.04` and install Task through `.github/actions/setup-task`. Only the `lint` job needs golangci-lint, so only it caches `~/go/bin`, keyed on the Go version and `tasks/go.yaml`, so a Go or tool upgrade rebuilds the binaries once. Renovate updates the `go install` pins in `tasks/go.yaml` and Task's version in the setup-task action through regex managers in `renovate.json`. Every third-party action is pinned to a full commit SHA with its release tag in a trailing comment (`uses: actions/checkout@<sha> # v7.0.1`), so a moved or compromised tag cannot change what CI runs. When bumping an action, resolve the new tag to its commit SHA (dereferencing annotated tags) and update both. M2 adds prek, integration tests, test reports and coverage.
